# DLoop 3.6.4：功能交付交付摩擦修复

基于冻结标签 `v3.6.3`，当前为 `frozen`，由 `v3.6.4` 标签固定。本版本修复正常交付中已观测的行为不一致与接入缺口，使用补丁版本 3.6.4；不改变 README 中的稳定设计意图，不新增审批或修改占用模型，不迁移其他版本作业。2026-09-09 用户授权收口、冻结、创建 PR 并合入；不包含在目标项目 上替换安装或继续旧版本需求。下文保留各开发批次当时的记录，最终状态见末节。

## 事实与交付目标

现有流程存在三类接入问题：任务准备允许的通配范围在实施后被判为越界；已打开编辑器时批处理采集无法使用；部分执行阻断未归入当前交付项的复盘记录。本版围绕这些通用流程问题修复。

目标是让相同工作在开工前取得清晰范围，在当前编辑器完成采集，并在需求复盘中看见完整的执行阻断。历史损坏档案、正常审批保护和策划配置准备不足不作为本版工具缺陷处理。

## 实现

### 文件范围

任务包统一解析入口拒绝星号、问号和方括号通配表达，适用于准备、检查和启动。具体文件与目录仍按原有规则工作，目录包含其子项；生成代码及元文件须纳入范围。输入准备结果与 Skill 同时提示产品范围不能包含 DLoop 自有档案。没有增加通配展开、范围变更或熔断恢复状态。

### 当前编辑器截图

保留两个 UI 业务入口。没有显式批处理参数时，调研入口生成当前项目下的临时截图请求并返回等待采集；此时不写正式 UI 模型、计划和批准。协调者用 Unity MCP 在已打开项目调用现有截图器，保持并恢复临时环境变量，再通过 `--capture-manifest` 交回真实清单。

清单接入复用原有实际资产身份、GUID、内容摘要、截图、区域和阶段校验，成功后才通过原有事务发布到规范档案。初版未修改 Unity 截图器 C#；9 月 9 日真实复验后，按下文记录修正临时采集场景，不另建截图状态或允许手改模型。批处理仍可显式选择，环境变量不再自动启动第二个编辑器。未匹配到 Prefab 的调查仍直接形成正常跳过。

### 摩擦复盘

`friction-summary` 的 `execution_breakers` 直接投影当前需求执行账本中的熔断报告和切片状态，保留触发事实、已验证成果与未完成项。旧切片终止后仍可查到当时熔断，不将终止当作根因修复，也不向旁路日志复制一份执行状态。

文档级命令按照文档标识规定的所属交付项归属操作失败与恢复；仅同一交付项的文档批次归属，跨交付项批次保留全局归属。不改写历史空归属记录，不通过全文猜测旧事件。

### 入口指引

网页需求先读取并形成带链接和定位的本地 UTF-8 材料；已有初始化不替换来源。同层计划资料用相关引用，不能作为硬依赖。相关说明跟随当前 Skill 与输入准备结果投递。

## 补充：标注底图空白与原图链接失效

补充检查发现，派生 SVG 以外部链接引用 PNG 时，部分 Markdown 阅读环境不能展示截图底图。将原图内嵌 SVG 后，取样区域像素恢复一致；本次修复针对媒体引用方式，不改变截图事实或原有业务判断。

Markpad 2.6.13 的发布源码将普通 PNG 链接交给外部网址打开流程；相对 PNG 地址被解析为应用页面地址，而非磁盘图片。用该版本的实际点击处理代码复现，旧链接没有进入图片预览，新文内图片进入放大预览且不调用外部打开。未复现用户安装进程整体卡死的底层原因，不将处理代码实验等同于桌面程序完整验收。源码依据：[点击处理](https://github.com/sftwrdotdev/Markpad/blob/v2.6.13/src/lib/MarkdownViewer.svelte#L2315-L2335)、[文内图片解析](https://github.com/sftwrdotdev/Markpad/blob/v2.6.13/src/lib/utils/markdown.ts#L471-L490)。

放行原因是原有检查验证模型、证据身份和文件归属，没有验证最终 SVG 在 Markdown 图片环境中的可见内容；原有测试使用协议夹具，没有覆盖成品显示。前一轮 3.6.4 验证同样遗漏了这一层。此问题妨碍 UI 方案审阅，不能当作可容忍的不完整，也不能归为正常业务跳过。

修复将真实 PNG 字节内嵌 SVG，原图使用 Markdown 图片直接展示；保持原截图和标注事实。轻量回归验证内嵌字节与原证据一致，公开发布回归检查不再生成普通 PNG 链接。Skill 要求交付前查看最终 Markdown 的底图、标注和原图，不能仅凭机器 PASS 宣称附件可用。

新增 `tests/check_ui_annotation_render.cjs` 用真实浏览器渲染整份 Markdown，核对文内原图、PNG 跳转链接数量和指定无标注覆盖区域的底图像素。命令参数为计划路径、原图路径、输出截图路径、取样区域的 X/Y/宽/高；依赖 playwright、sharp、marked，并设置 `DLOOP_TEST_CHROME`。本次同一检查对修复前备份返回失败（原图不可见、1 个 PNG 链接、像素匹配 0），对修复后原文件返回通过（原图可见、0 个 PNG 链接、像素匹配 1），并人工查看整份渲染截图。

按用户本次明确授权，仅修复 Dev 的这份 Markdown 和派生 SVG，并由 Dev 已安装的 3.6.3 文档确认入口登记非语义变更。原文件备份保存在 `local-artifacts`。文档语义版本仍为 0.1.0，未使下游文档失效；截图、采集清单、UI 模型、实施账本和安装锁摘要保持一致，功能元数据仅由正常确认流程更新时间。没有升级安装、迁移模型、重新截图或重新批准需求。

补充修复后的全量验证：工作流 334 项中 333 通过、1 项条件跳过（约 190 秒）；根目录 36 项中 35 通过、1 项真实 Unity 条件跳过（约 156 秒）。浏览器成品验证与 Markpad 点击处理实验另行执行，不计入这 370 项单元与集成测试。

## 2026-09-09 补充：四类业务结果遗漏

本次补强聚焦四类通用需求偏差：操作去向改变、内容覆盖不完整、信息落点混淆和状态变化缺少触发动作。沿用 3.6.4 的开发计划修订场景规则与交接材料，不新增命令、批准点或档案格式。

### 正常流程中的原因与改动

| 合法输入与执行路径 | 可能遗漏的结果 | 本次落点 |
|---|---|---|
| 协调者从原文形成需求、选择现有组件形成设计，任务包只引用设计；交接此前只自动补设计入口 | 实施与评审沿同一方案接受复用方案改变操作去向的原意偏差 | 需求和设计规则保留原始定位；交接同时补入未引用的批准需求入口，实施/评审/返修共用。已有章节选择保持，不重复整份读取 |
| 缺少配置时先实施可用页签，其他页签列为后续或隐藏；每个切片只检查自己的边界 | 局部通过被误作完整功能交付，延期恢复没有承接 | 计划反查每项业务承诺；缺项标明承接切片或输入负责人、影响和恢复条件；依赖补齐时核对受影响结果，最终验收明确偏差 |
| 需求用“用户信息”“排序结果”概括，设计和切片继续沿用 | 不同对象的展示数据与排序含义混淆或遗漏 | 相关场景落实对象、显示位置、调查核实的数据来源和可观察结果；任务包与角色要求同步投递 |
| 设计只规定收到后端更新后切页，实施分别完成时间状态显示和回包路由 | 时间归零没有触发获取新状态 | 设计与验收覆盖触发者、获取新事实、回包更新和条件未满足时保持原状态；不另建前端业务状态或强制轮询重试 |

机器结构检查不会自动判断方案是否偏离原需求。本次确定性修复保证必要需求材料能到达下游；语义完整性由已有协调、实施和评审职责执行，不声称新增了自动业务判定门禁。全部业务说明复用现有需求、计划、契约和验证正文，不另建覆盖表格式或第二份状态。
