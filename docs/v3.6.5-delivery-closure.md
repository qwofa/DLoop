# DLoop 3.6.5：交付表达与验证记录改进

基于冻结版 3.6.4（历史提交已脱敏），按用户明确要求使用补丁版本 3.6.5。经设计符合性评估后，用户于 2026-09-10 授权冻结、创建 PR 并合入。当前为 frozen，由 `v3.6.5` 标签固定；本次冻结不包含安装到目标项目。改动修正已有交付流程的表达和输入准备缺口，不新增审批、迁移旧版本作业或引入第二套业务状态。

## 需求与实现

| 正常流程中的问题 | 本版处理 | 验收结果应可观察为 |
|---|---|---|
| 从原始需求提取 UI 条目并匹配 Prefab 后，分类与列表两个位置被概括成“状态提示”，机器 PASS 仍可能遗漏入口提示 | 在现有场景指引、初始化模板、任务包输入说明及评审角色中强调显示位置、触发与不处理条件，回查原始来源；不强制按节点拆场景 | 同一场景能承接打开、切类、默认选中、主动查看、再次打开的区别；机器结构覆盖不被当成业务语义证明 |
| 独立评审写完问题或证据后，提交才发现目录不同 | prepare-action-input 增加 review-issues 与 review-verification，按唯一候选和独立身份生成规范路径与精确结构；角色与下一动作同时返回准备入口 | 原样执行返回参数即可生成问题和证据文件，填入实际发现后可提交；重复准备不覆盖内容、不登记评审、不改变候选 |
| 用户接受静态交付但不冻结档案，验证中及冻结字段 pending 易被读成没有验收 | delivery_view 增加只读 delivery_summary，分别投影批准、候选证据、未验证边界与档案保留状态；分享复用同一摘要，入口明确生命周期含义 | 已接受、运行未验证和未冻结同时可见；批准失效时不继续显示已接受；不自动填验证通过或冻结 |
| 外部工具重载等返工不在 CLI 自动异常中；后续缺项散在正文 | 摩擦入口直接给必需参数，纳入真实外部工具返工；汇总已报告代价、未知代价、额外动作、重复证据及可选补记入口。验证正文集中维护后续接入清单 | 没计量保持未知；恢复补记归于原事件；新阶段可直接引用功能、输入、提供方、接入位置、验证方式和状态 |

## 工程边界

- 仅处理当前版本正常 Skill、命令与合同产生的作业；流程改进不用于继续、迁移或重写旧版本档案。
- 需求覆盖的语义判断仍由执行和评审承担。未增加自然语言解析门禁；模板及机器检查不能证明模型会正确理解全部需求。
- 保留最终验收和冻结的既有事实源；新增汇总为即时投影，候选未列边界不代表运行验证完整。
- 后续接入清单直接位于既有验证文档，按已有文档确认流程维护；不新增缺项状态机，也不编造提供方或交期。
- 摩擦汇总仍不阻断业务提交；自动正常门禁不是工具缺陷，事件数量不是实际投入。只对已知返工补记，不回扫全部历史。
- 不修改游戏代码、Prefab 或 Unity 编辑器截图实现。安装与卸载在独立临时项目验证。

## 验证计划

通过当前公开命令完成候选提交、评审输入准备、只读交接、评审通过、最终接受和只读分享链，检查未运行边界保留。补充外部返工与恢复记录、身份不独立、无候选和重复准备等路径。运行相关回归后执行工作流、发行、安装与卸载全量测试；两份 Skill 执行结构校验。

独立模型行为实验未执行。现有测试只证明材料投递、状态与命令行为，不把它们写成模型业务判断通过。

## 2026-09-10 验证结果

- 新增及扩展的公开命令回归覆盖评审文件准备与提交、同身份拒绝、无候选拒绝、重复准备不覆盖、静态接受但不冻结、未验证边界保留、验证正文语义变化后接受失效、分享摘要和外部工具恢复补记。
- 多位置新获得提示样本加入原需求交接回归：实施、独立评审和返修始终取得完整原场景，原始材料与任务包不被改写。此项验证材料到达，不证明模型已经理解全部行为。
- 工作流全量运行 338 项，首次 336 通过、1 项失败、1 项源码环境安装态检查按条件跳过。失败为分享输出精确字段集合尚未包含新增 delivery_summary；同步当前输出合同后，输入准备 11 项、交接 12 项、分享路径 16 项全部通过，其他已通过结果复用。
- 根目录发行、安装卸载和轻量 UI 回归 36 项：35 通过，1 项真实 Unity 采集因未设置独立编辑器测试环境按条件跳过，耗时约 143 秒。没有修改截图 C#，不把条件跳过计为真实采集通过。
- 上下文回归 41 项通过，保留原有 6 KiB 协调摘要限制。首次新增汇总超限后，改为候选形成后才展开边界，压缩重复指引，没有放宽预算。
- 两份 Skill 结构校验、修改 Python 文件语法检查与差异空白检查通过。未运行独立模型行为实验，未操作目标项目 的业务文件、旧档案或安装。

复核发现原 Skill 的“任一未验证边界均阻塞”与接受限定范围交付的实际规则不一致；改为范围内必要验证未完成才阻塞，用户明确接受的延期与范围外未验证继续保留。没有降低候选提交前登记验证必须通过的门槛。
