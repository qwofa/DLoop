# DLoop v3.9.0 场景验收与工作流摩擦修正

状态：`frozen`。基于公开主线 v3.8.1，冻结日期为 2026-09-18，由 `v3.9.0` 标签固定；未安装到使用者项目。

## 交付范围

默认交付改为业务场景验收导航：本次变化、产品内入口、准备条件、实际验证层级及结果、待完成项。操作步骤与证据折叠，截图和元素定位按需查看。实施开始时生成同一份验收记录，先验证入口，再逐场景补结果；候选和最终展示引用同一文件，不在结尾重新抄写逐控件交互。

验证明确区分静态检查、客户端隔离验证和实际环境验证。有未完成项仍可发布当前成果页，但必要实际验证未通过时不能最终批准。用户可以直接在产品内验收，同一次回复用于登记最终结论，不再重复批准 HTML 描述。候选与独立评审、证据新鲜度、业务范围和最终批准要求继续有效。

用户明确延期或本期不要求的场景，即使没有提交验收记录，也从已批准材料要求中保留场景与范围依据，显示未提供验证结果，不补造步骤和证据。后续补交记录时由实际结果替换该说明，不重复展示同名场景。其他必要局部交互仍须通过验证。详细合同中的提交示例、材料更新及展示要求统一使用场景验收方式。

材料更新会清理被替代的交付证据引用，保留仍被局部交互说明引用的证据；调整验收记录的定位说明后，不再因旧引用阻塞最终验收。页面和命令返回的就绪状态共用完整材料检查结果，证据过期或其他材料检查未通过时均不显示就绪。

只因文件漏登而熔断时，可通过 `resolve-slice --action amend-scope --amendment-file` 补登记原批准业务范围内的实际文件。修订保留正文、契约历史、阻断历史及漏登原因，不接受目录扩容，不消除业务或依赖阻断。新契约仍须重试、重新验证并交独立评审。

新增文件的恢复边界是补登记时保留的现场；原授权范围仍保留实施起点。工具不声称拥有此前未受管文件的修改前正文。候选明确列出这些保留文件和授权依据，不把它们隐去或当成未发生变化。

已有 3.8.1 生成器预检、内部材料归属和开工确认修复继续沿用。本版不迁移或接续旧版本作业，不改动真实使用者项目中的业务实现和旧验收记录。

## 验证范围

- 场景记录从准备到候选、独立评审和页面生成的完整路径。
- 静态检查可展示但不能通过实际验收门禁，结果更新后复用同一文件。
- 证据变化使旧结论失效，缺项不以截图或文案替代。
- 范围修订保留代码与绑定，候选仍包含全部补登记文件；目录扩容及其他业务阻断仍拒绝。
- 现有契约、候选、审批、安装与版本元数据回归。
- 浏览器默认和窄窗口中的场景浏览、步骤/证据展开及可选界面定位。
