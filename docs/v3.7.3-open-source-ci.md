# DLoop 3.7.3：开源准备与持续集成

基于冻结版 v3.7.2，发行状态为 `frozen`。发行元数据、两项 Skill、Unity 包和快照版本统一为 3.7.3，由 `v3.7.3` 标签固定。

本版新增 MIT 许可证、按能力接入的依赖说明，以及可迁移到新仓库的持续集成。它服务于现有工作流的验证和外部使用准备，不改变 README 中的稳定设计意图，也不增加业务审批、恢复机制或跨版本作业兼容。

## 持续集成

每个 PR、默认分支推送或手动触发时，运行 Windows 核心与快照、安装与发行，以及独立的凭据检查。核心集合包含 UI 数据与固定模板的现有回归，并运行评测工具自身的测试。安装测试使用本次检出的源码包，不绑定原仓库地址，不下载旧标签代替当前变更验证。

必需的 Git、SVN、svnadmin、PowerShell 缺失时失败；空测试集合和未登记跳过同样失败。源码安装态检查由发行及真实安装回归承接；真实 Unity 编辑器测试因缺少环境单独列出，不计为通过。没有接入真实浏览器、真实模型或实际 Unity 业务端到端自动运行。

首次云端运行发现英文 Windows 的 SVN 客户端不能无损接收中文路径及提交组名称。CI 对临时客户端副本声明 UTF-8 进程编码，并在回归前执行真实中文往返检查；不改产品逻辑或系统区域设置，不删除失败用例。初次失败记录保留在 PR 的 Actions 历史中。

CI 只有代码读取权限；迁移时保留 `.github/`、源码与测试即可。新仓库的 Actions 开关和合并检查要求需单独设置。公开仓库沿用 `qwofa/DLoop`，安装入口与标签下载地址一致。完整范围、跳过说明和本地复现入口见 [CI 说明](ci.md)。

## 许可与依赖

仓库采用 [MIT 许可证](../LICENSE)。运行依赖按能力说明，Unity MCP 不绑定实现或版本，可选实现仅作参考；详见 [依赖说明](dependencies.md)。

## 发布与隔离验证

首次公开发行在新的 `qwofa/DLoop` 仓库中仅导入本版源码，以单次初始提交开始，不带入原开发仓库的 Git 历史、旧标签或 PR 引用。历史版本说明保留为变更记录，不代表公开仓库提供对应旧标签。

2026-09-14 在可丢弃的 Unity 2022.3.62f2c1 项目中完成以下实测，使用 CoplayDev MCP for Unity 10.0.0 作为本次连接实现；这不是对 MCP 实现或版本的限制：

- 从本版源码包完成安装；实际 Codex Skill 列表识别到两项已启用的 3.7.3 Skill。
- Unity 编译并加载截图包；独立真实编辑器采集测试 2 项通过。
- 通过 MCP 选择隔离项目，执行实际运行模式的指针点击；启用按钮使计数加一，禁用按钮不改变计数。
- 由正式命令生成采集请求，通过 MCP 调用已安装截图器并导入真实 800×600 截图。采集前后的活动场景、场景状态和 Prefab 文件保持一致。
- 由正式命令生成内部核对 HTML，并在浏览器检查截图、交互说明和原始尺寸切换。
- 完整卸载两项 Skill、共享工具与截图包，交付 HTML 和档案仍保留。

这组实测覆盖环境接入和交付材料链路；示例未经过真实模型的完整需求实施与最终业务验收，内部核对页面不宣称为业务终验通过。云端 CI 的缺少编辑器跳过项与本次本地实测分别记录；公开下载与 CI 结果可在 [发行页](https://github.com/qwofa/DLoop/releases/tag/v3.7.3) 和 [Actions](https://github.com/qwofa/DLoop/actions) 查阅。
