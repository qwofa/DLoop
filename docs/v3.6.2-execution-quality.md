# DLoop 3.6.2：实施连续性与交付质量

基于冻结的 `v3.6.1`，按用户指定版本 3.6.2 修复既有流程卡点，当前为 `frozen`，由 `v3.6.2` 标签固定。不改变大型功能交付定位、六阶段、单一 SVN 修改租约或人工业务批准；不修改 README 的稳定设计意图。

## 本版需求与方案

1. 实施或返修中发现需要增加验证时，由协调者使用窄范围补充入口追加验证、提高强度并说明新风险。工具保留实施身份、工作区、租约和历史，递增契约版本；旧检查点不能再用于提交，生成输入自动携带当前契约版本，旧输入原样重交也会被拒绝。不得借此删除验证或改变业务目标、写入范围、验收、依赖与回退。
2. 实施角色直接取得普通失败继续诊断、何时记录检查点、新风险和真实边界失效的处理规则。任务包材料是只读调查起点，可查当前调用链及已有项目惯例；修改权限仍由写入范围确定。
3. 独立设计与候选评审可核对相关项目事实。候选评审沿真实流程检查正确性与维护成本；批准设计存在问题时明确退回，不以符合方案代替实现质量，也不强制测试数量或空洞检查表。
4. 交接准备成功默认只返回就绪、身份、消息和下游读取入口；显式展开时才返回完整角色视图。两种响应使用相同检查，下游继续独立读取，不缓存就绪结果。
5. 执行基线摘要与恢复内容由一次文件读取形成，重叠写入范围不重复读取同一文件。保留现有恢复格式与工作区变化检查，不增加跨命令缓存。
6. 用相同初始代码和业务要求进行独立、隔离的真实编码对照，保存实际修改、测试和可取得的耗时/工具事实。区分局部编码实验与完整 Unity 项目交付，不能用自报动作或规则测试宣称质量、速度改善。
7. 最终验收角色统一只提交建议，业务决定仍由用户确认。

- 验证补充成功、失败不写入、重复请求、旧检查点失效、补足后提交和返修历史保持有效。
- 交接简短与完整模式具有相同资格和缺项结果；角色能独立取得当前任务规则。
- 基线读取次数、摘要与恢复内容一致，继续覆盖中断恢复及事务失败。
- 运行工作流、发行安装与卸载、评测工具回归及 Skill 结构检查。
- 对照实验记录实际结果及局限，未取得的模型指标明确留空，不估算。
