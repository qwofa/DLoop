# DLoop 3.4.5：大型实现交付边界

## 需求结论

DLoop 只承接需要跨轮规划、实施切片、独立候选评审和最终集成验收的大型实现工作。普通局部修改、纯文档整理、调查结论或没有实现切片的事项在常规任务中直接完成，不初始化 DLoop，也不能借实施与验证总览进入最终验收。

“大型”不由代码行数、文件数、预计工时或固定切片数量猜测。可执行边界只有一条：进入最终验收的交付必须至少形成一个可独立验收的实现切片，并拥有已经独立评审通过的固定候选。切片方案原有的非空要求保持不变。

## 零切片来源与处理

零切片来自旧的文档交付旁路：没有建立或执行切片方案时，只要把实施和验证总览标为完成，最终评审与最终批准仍可接受空候选集合。这不是正常切片方案产生的结果，因为切片方案一直要求至少一个切片。

3.4.5 删除该旁路：

- 活跃阶段没有已接受候选时，不再建议进入验证，而是要求形成并批准至少一个实现切片；协调者仍可取得计划和实施文档的写入目标，没有实现工作的事项退出 DLoop。
- 已经人工进入验证但仍没有已接受候选时，统一交付视图直接路由回实施阶段，不生成最终评审角色合同。
- 最终评审和最终批准都要求至少一个已接受候选，并始终要求候选集合、唯一工作区和集成确认绑定。
- 当前版本的状态校验拒绝空候选集合的历史最终批准记录；不增加旧状态兼容或迁移分支。

## 特例审计

本版本删除零切片交付旁路，并将实施范围收敛到正式 SVN 工作区：不再支持 Git 或无版本控制工作区回退；删除观察模块及通用扩展分发层；全工作流只保留一条修改租约。以下保护继续保留：

- 候选或最终工作区漂移时阻断，避免验收对象与实际代码不一致。
- 全局唯一修改租约、进程中断和熔断后的原范围重试，避免未收敛修改被另一棒次接管或丢失。
- 需求、设计、计划和验证材料失效时阻断，避免按旧业务事实继续实施。
- SVN 不可用或无法取得工作区状态、修订时明确失败，不以缺少变化边界的工作区启动实施。
- 显式 DloopUI 中 Prefab 不存在、匹配不唯一或截图失败时的跳过，避免规划工具虚构产品资产；跳过不能替代 DLoop 实现切片。

熔断后只允许保持原契约、原方案绑定和写入范围重试，或由人工恢复授权范围与 SVN 工作区基线后终止。需要前置、替代或重新划分时，先终止原切片，再修改方案并创建新切片，不保留专门的等待、修订恢复或替代终态。

尚未开始实施的草稿、检查失败或已就绪切片可以通过现有终止入口标为放弃，保留契约和检查历史。它们没有执行身份和修改租约，因此终止只更新切片记录；新方案可移除对应声明，旧记录不再阻断新切片和最终验收。

## 改动范围

- 修改最终候选绑定、最终批准、当前状态校验和统一交付视图。
- 删除零切片实施记录替代候选的评审材料与动态任务字段。
- 删除观察扩展、非 SVN 工作区回退、多修改租约和专门熔断恢复分支。
- 更新 DLoop 入口、实施、评审、验证说明及对应回归测试。
- 档案格式、术语格式、切片方案格式、候选与评审格式保持不变。
- 3.4.5 完成验收后冻结并由 `v3.4.5` 标签固定；冻结不包含向用户项目安装的授权。

## 验收

- 完成实施与验证总览但没有候选时，最终批准明确拒绝。
- 验证阶段没有已接受候选时，统一交付视图回到实施要求，最终评审角色视图不形成。
- 至少一个切片已独立评审通过后，现有集成确认、最终评审、最终批准和冻结闭环继续通过。
- 首次实施前协调者可更新计划和实施文档，但不能提前取得验证文档写入目标。
- 契约检查失败后可终止旧记录、调整方案并验收新切片，最终批准不再被旧记录阻断。
- 候选漂移、多工作区最终绑定、未释放租约和陈旧材料的保护无回归；已开始实施的切片仍须满足工作区恢复要求才能终止。
