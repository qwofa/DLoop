# DLoop v4.1.0 交付分级（开发中）

基于已发布的 v4.0.3，尚未冻结。版本号、发行清单、安装路径和标签未切换，发布时统一处理。

## 范围

- `init --tier standard|lite` 选择交付分级，省略为 `standard`；分级写入 `feature.json` 的 `delivery_tier`，创建后固定；`lite` 作业的交付视图在 `trusted_machine_facts.delivery_tier` 返回 `lite`，标准作业不返回该字段，以保持协调者上下文 6 KiB 预算（首轮 CI 中带该字段的标准摘要为 6145 字节）。
- `lite` 生成调查、设计、计划总览的说明占位，不维护、不确认：
  - 交付视图在需求共识后直接进入切片阶段，不再要求设计、计划总览；
  - `start-slice`、`submit-slice` 与评审的实施输入只检查需求类文档；
  - 交接不再自动补入设计入口，任务包指引示例同步省略；
  - `validating` 与 `frozen` 的文档门禁跳过三个占位类别；
  - 进行中阶段只开放 `implementation`、`validation` 动作；`stage-action --stage architecture` 返回 `LITE_TIER_STAGE_NOT_APPLICABLE`。
- `lite` 与 `--configuration` 互斥；以另一分级重复初始化返回 `DELIVERY_TIER_CONFLICT`；`snapshot-fork` 沿用源快照中的分级。

## 不变部分

需求总览确认与需求共识、切片方案批准、切片契约与七项检查、全局修改租约、工作区保护、候选固定、评审身份独立、验证总览、集成确认、冻结与 `completion_claim` 在两级中共用同一实现，没有为 `lite` 增加放宽分支或第二套状态。
