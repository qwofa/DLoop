# v4.0.3 Claude Code 与 OpenCode 宿主支持

状态：`frozen`。冻结日期：2026-10-21。基于已发布的 v4.0.2；增加宿主支持，按用户指定使用 4.0.3。通过 PR 合入公开主线，不自动升级使用者的正式项目；在线安装依赖同名版本标签。

## 范围与执行计划

本次独立结果是：同一份 DLoop 可从 Claude Code 或 OpenCode 显式启动，继续使用现有项目档案、工具和独立评审流程。安装与入口属于同一接入结果，合并实现和验收；模型配置仍由宿主承担，无需拆出模型网关或 agent 调度器。Codex、Cursor 的入口保持不变；OpenCode 复用已有 Skill 目录和原生显式入口，不增加第三份载荷。

- 从同一源码安装两项 Skill 到 `.agents/skills/` 与 `.claude/skills/`，纳入同一安装锁和升级、校验、卸载、回滚流程；不采用链接或第二套安装器。
- 入口使用显式选择与能力要求；补充主协调者使用的宿主指引，沿用原生子 Agent、独立上下文和单线实施。
- 补充 Claude Code、OpenCode 的 DLoop MCP 与 Unity MCP 连接说明；安装器不覆盖用户的宿主配置或其他 Skill。
- DeepSeek 通过 Claude Code 或 OpenCode 的宿主配置使用，不增加模型请求、密钥或自动切换逻辑。
- 工作流核心仅更新当前版本目录与快照版本常量；不修改业务状态或档案结构，不跨版本接续旧作业。

## 验证范围

安装回归覆盖两处 Skill 字节一致、受管归属、旧布局升级新增目录、重装、卸载及失败回滚；保留其他 Claude 配置、MCP 配置与项目 Skill。运行发行安装集合和受版本路径影响的核心回归。

真实宿主验收区分 Skill 发现、MCP 连接与模型执行。完整模型验收须在临时项目完成实施、独立评审及结果登记；DloopUI 另需真实 Unity、截图理解和交互验收。尚未实际执行的范围不得记为通过。

## 实际验证记录
