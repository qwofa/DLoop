# DLoop v3.9.1 安装恢复与错误提示

状态：`frozen`。冻结日期：2026-09-20。基于公开主线 v3.9.0；线上安装在公开主线合并并发布 `v3.9.1` 标签后生效。

## 已确认的问题

旧安装的受管文件存在本地维护补丁，原安装锁仍记录发行时的摘要。用户执行正常升级命令时，3.9.0 在第一处摘要不一致时退出，仅显示文件路径与 PowerShell 堆栈。完整性检查阻止了未经处理的覆盖，但用户缺少直接完成升级的路径。

## 修复范围

- 只在安装较新版本时接受旧安装锁中已登记、路径与文件类型合法的文件内容变化。先校验整个旧安装的归属，再展示全部变化路径。
- 有修改或新增内容时，先把全部已登记旧载荷、新增文件和目录及原安装锁复制到 `.scratch/dloop-install-backups/<旧版本>-before-<新版本>-<唯一标识>/payload/`，核对备份摘要，保存修改、新增与移出路径清单后才开始替换。空目录也保留；原安装锁保持原文，不伪造摘要，不要求用户回退本地补丁。
- 备份失败时旧安装不变；后续升级失败沿用安装事务恢复原文件、安装锁和旧作业。备份独立于旧作业归档，成功或失败均保留，可供维护者查阅补丁。
- 受管目录内新增内容不再阻断升级。不冲突的保留原位；与新版文件同名的文件或目录、挡住新版目录的文件，在完整备份后移出，失败时连同空目录恢复原位。新增内容不纳入新版安装锁。
- 可重新生成的已识别 Python 缓存继续按原安装规则清理；缓存目录内的笔记、未知子目录等新增内容仍按用户文件备份保留。
- 已登记文件缺失或类型变化、链接、路径越界和安装锁归属不明仍不自动处理。同版本重装、验证、卸载继续要求已登记文件一致，卸载仍拒绝含未登记文件的受管目录；不迁移旧作业。
- 失败时控制台展示原因和独立诊断日志位置，完整堆栈写入系统临时目录中的日志文件。安装事务回滚后明确说明恢复结果。
- 维护工具时在源码中修复，通过新版本安装交付；不直接修改使用者项目的安装锁来认可补丁。

## 验证范围

- Git、SVN 项目中旧安装含多文件本地修补：列出所有路径，备份正文及原安装锁，升级后验证通过，业务改动和旧作业保留。
- 备份期间、备份完成、旧作业归档后、安装记录写入后的故障：验证恢复范围与补丁留存。
- Git、SVN 项目中新增文件和空目录：不冲突内容原位保留，三种路径冲突备份后升级，安装记录只登记新版载荷；混合本地补丁时验证备份、移出、替换中途失败恢复及再次升级。
- 一行安装的成功、失败及日志展示，中文路径与控制台编码，当前版本安装、校验、重装和卸载回归。
- 版本元数据、两份 Skill 与当前版本工作流回归。
