# DLoop 3.3.8：接缝减摩与显式恢复

## 1. 版本定位

- 目标版本：3.3.8 冻结版
- 基线版本：3.3.7，提交 `历史提交已脱敏`
- 档案格式：保持 3
- 术语格式：保持 2
- 发行状态：`frozen`

本版本不增加新的常驻保护层。核心目标是删除收益不足的宿主退出拦截，把“执行是否完成”重新交给持久业务状态与显式操作；同时修复此前在任务包、工作区范围、角色交接、响应丢失重试和摩擦记录上的高频接缝问题。

## 2. 已观察到的摩擦及源头

| 摩擦 | 源头 | 3.3.8 处理 |
| --- | --- | --- |
| 正常结束任务也可能被拦住 | 把普通退出当成业务提交边界，而宿主事件缺少完整业务目标 | 删除整个宿主退出拦截链路；只认显式提交 |
| 中断后不清楚该继续还是重开 | 临时宿主登记与正式工作流状态存在两套身份来源 | 只从持久活动棒次、执行身份和修改租约恢复 |
| 响应丢失后重试提示身份已使用 | 启动和检查点只防重复写，没有识别完全相同的重试 | 相同身份、输入、契约和工作区返回原结果；内容变化仍拒绝 |
| 工作区范围偶尔包含工作流自身材料 | 产品写入范围和受管状态目录没有硬边界 | 启动前拒绝受管目录，仅放行精确的稳定 UI 模型文件 |
| 角色明明正确却因动作参数不匹配被退回 | 角色和动作由调用方分别填写，形成两个事实源 | 非协调角色从角色合同推导动作，不再信任重复参数 |
| 任务包经常漏字段或两份字段不一致 | 切片契约与顶层任务字段重复表达同一业务事实 | 输入只保留切片契约，校验后生成兼容投影 |
| 相同错误反复增加摩擦记录 | 日志没有稳定问题身份、尝试和关闭生命周期 | 同一问题复用标识，输入改变记新尝试，成功自动关闭 |
| UI 视图可以脱离工作流单独覆盖 | 运行时暴露独立生成入口 | 视图只允许通过配置同步统一写入和更新摘要 |

## 3. 设计决定

### 3.1 普通退出不是业务事件

业务结果只有三种显式入口：完成、失败、中断。关闭任务窗口、停止一次 Agent 或应用异常退出都不自动代表其中任何一种，也不改变正式状态。

活动棒次已经持久保存以下恢复事实：

- 当前交付项和切片；
- 实现执行身份；
- 修改租约和执行前工作区基线；
- 最近检查点及其契约、验证和工作区摘要；
- 固定候选与独立评审状态。

因此源头方案不是用更严密的退出规则补齐所有接缝，而是删掉退出规则，让下次进入时直接读取这些正式事实。

### 3.2 中断恢复流程

重新进入后：

1. 读取全局和交付项状态；
2. 根据角色投影取得当前棒次、实际阶段和唯一下一动作；
3. 结果已经明确时，继续使用原执行身份提交；
4. 确认该棒次不能继续时，显式提交 `interrupted`；
5. 系统恢复执行前工作区基线并释放租约；
6. 需要继续目标时，由主协调者按正式状态建立新的执行身份。

这条流程不会猜测异常退出，也不需要宿主保留临时登记。

### 3.3 响应丢失重试

启动请求的幂等条件同时包含：

- 相同执行身份；
- 相同规范化任务包；
- 相同工作区；
- 当前活动棒次和租约仍指向该身份。

检查点请求的幂等条件同时包含：

- 相同检查点身份和规范化请求；
- 相同当前契约摘要；
- 相同工作区内容摘要和防护摘要。

全部一致时返回原持久结果并标记为幂等；任一条件变化时返回身份冲突，不把新工作误合并到旧结果。

### 3.4 产品写入与工作流状态隔离

任务包写入范围在取得租约前进行规范化检查。以下范围直接拒绝：

- 工作流根、全局状态和锁；
- `.scratch/dloop-v3` 本身或任一父级范围；
- 交付项内部的工作流状态、阶段文档和派生材料。

唯一例外是精确到 `.scratch/dloop-v3/outputs/<feature-id>/ui-model.json` 的稳定 UI 模型文件。放行文件不等于放行其父目录。

### 3.5 角色动作与任务契约单一事实源

协调者和独立冷读仍需显式动作，因为它们可以进入多个阶段。设计评审、实施、候选评审和最终验收的动作由角色合同唯一推导；调用方即使带了陈旧动作，也不会制造第二套门禁。

角色暂时不可进入时返回当前实际阶段、所需阶段和统一交付视图中的精确下一操作，不再给笼统的“返回协调者”。

任务输入中的业务目标、范围外、验收场景、验证和回退点只在切片契约里声明。工具完成合同检查后生成供既有消费者读取的内部投影；输入若继续手工携带这些重复字段会被拒绝。

### 3.6 摩擦生命周期

每个问题的稳定关联键由交付项、操作、错误码、分类和业务目标组成，消息正文只影响本次输入指纹：

- 第一次异常追加 `failure`；
- 完全相同的开放异常不重复写入；
- 同一问题但输入变化追加 `attempt`；
- 对应操作成功追加 `resolved`；
- 预期阶段门禁追加 `guard`，但不进入开放摩擦统计。

用户主动中断、内容评审未通过和正常业务依赖缺失不伪装成工作流故障。摩擦旁路写入失败只产生警告，不改变原操作结果。

## 4. 改动范围

### 4.1 删除

- 宿主退出事件转换适配目录；
- 会话和执行临时登记读写；
- 父任务与子任务退出专用审计入口；
- 安装器中的退出事件配置、验证、禁用、升级和回滚分支；
- 对应单元测试、命令示例、信任提示、黑盒验收说明；
- 人工关闭摩擦命令；
- DloopUI 独立视图生成命令。

### 4.2 修改

- 执行启动、检查点与工作区范围校验；
- 角色投影和下一动作诊断；
- 任务包规范化；
- 摩擦记录及命令成功收口；
- Plugin、Skill、README、安装说明、发行元数据和版本测试。

### 4.3 保持不变

- 六个交付阶段和人工审批点；
- 修改租约、候选固定、独立评审和最终验收；
- 受管档案、术语和工作流状态格式版本；
- 正式安装仍需专项授权，本次只在临时项目验证安装生命周期。

## 5. 复杂度、收益和维护成本

| 改动 | 复杂度 | 主要风险 | 预期收益 |
| --- | --- | --- | --- |
| 删除宿主退出拦截及安装分支 | 中 | 安装锁载荷清单或卸载回滚遗漏 | 消除正常退出摩擦和一整套宿主兼容成本 |
| 持久状态恢复说明与角色投影 | 中 | 下一动作指向错误阶段 | 中断后可直接接续，不依赖临时状态 |
| 启动与检查点幂等 | 中 | 把变化后的请求误判为相同 | 响应丢失可安全重试，减少身份耗尽 |
| 受管范围硬边界 | 低 | 误伤稳定 UI 模型 | 从源头避免工作流材料被产品切片删除或覆盖 |
| 任务契约单一来源 | 中 | 既有消费者仍依赖投影字段 | 降低漏字段和双份字段不一致 |
| 摩擦生命周期 | 中 | 关联键过宽或过窄 | 统计接近真实问题，不再被重复门禁淹没 |
| UI 视图统一同步 | 低 | 文档仍引用旧入口 | 防止模型、派生视图和状态摘要分叉 |

整体复杂度为中等，主要工作量在跨模块删除和回归验证，而不是新增机制。删除后的长期维护面显著小于 3.3.7。

## 6. 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 全新临时 SVN 项目安装 | 只写受管载荷和安装锁，不创建或修改 Codex 项目配置 |
| 已有 Codex 项目配置 | 安装、验证、卸载全过程保持原字节不变 |
| 相同版本重装 | 载荷一致时幂等成功 |
| 其他版本安装锁 | 在读取受管载荷前拒绝 |
| 完整卸载 | 删除安装锁证明归属的载荷，保留交付档案和 `svn:ignore` |
| 普通任务退出 | 工作流状态不变，没有额外进程或阻断 |
| 中断后重新进入 | 能从持久状态取得原执行身份和唯一下一动作 |
| 显式提交中断 | 恢复基线、释放租约，重复操作幂等 |
| 相同启动响应丢失重试 | 返回原交接，不新增已用身份 |
| 相同检查点响应丢失重试 | 返回原检查点，不重复追加历史 |
| 同一身份但内容变化 | 明确冲突，不覆盖原状态 |
| 写入范围指向受管目录 | 在取得租约前拒绝 |
| 写入范围精确指向稳定 UI 模型 | 允许进入后续门禁 |
| 非协调角色携带陈旧动作 | 依据角色合同取得正确动作 |
| 重复任务业务字段 | 拒绝并要求只修改切片契约 |
| 同一异常重复发生 | 复用一个开放问题 |
| 修改输入后再次失败 | 在同一问题下追加尝试 |
| 对应操作成功 | 自动关闭开放问题 |
| 预期阶段门禁 | 可观察但不计为开放摩擦 |
| 独立 UI 视图生成 | 命令不存在；只能通过配置同步生成 |

## 7. 完成标准

1. 代码、安装器、Plugin 载荷和公开命令中不存在宿主退出拦截能力。
2. 当前说明不再指导用户配置临时会话、退出事件或人工关闭摩擦。
3. 删除文件不再被 import、安装清单、测试或文档引用。
4. 受影响核心测试、DloopUI 测试、发行测试和临时安装生命周期测试全部通过。
5. Python 编译检查、PowerShell 语法检查、差异空白检查通过。
6. 不正式安装到目标项目 项目；冻结提交合入后创建 `v3.3.8` 标签，并把发行状态固定为 `frozen`。
