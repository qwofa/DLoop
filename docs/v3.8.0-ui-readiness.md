# DLoop v3.8.0 开工材料核对

状态：`frozen`，由 `v3.8.0` 标签固定。基于冻结版 v3.7.6；新增 DloopUI 行为使用次版本号，保留升级归档与安装卸载能力。未部署到使用者项目。

## 交付范围

DloopUI 调查后按业务需求核实预制体、协议、配置和需求描述。必要材料缺失、无法唯一选择或语义未明确时，保存集中缺项清单，停止整个需求的实施；允许继续调查和整理资料。协议和配置确实不涉及时须说明理由。禁止用计划新增、占位或延期绕过必要条件。

材料齐备并形成计划后，用户查看预期结果及每类材料的引用、用途，明确确认后才能实施。启动、恢复、返修和实施角色交接共用确认状态。更换依据或改变需求语义后重新确认；明确声明仅修正清单用途措辞、补截图、内部标注和不改变业务含义的实现调整不重复确认。最终验收继续独立执行。普通 DLoop 不新增批准步骤。

机器检查覆盖四类清单完整性、真实文件引用、预制体调查匹配、缺项状态与确认版本；材料的业务适用性由 AI 调查和用户核对负责，文件存在不能证明协议字段或需求语义正确。

## 验证范围

- 缺少任一必要材料、歧义、错误路径和占位状态不能开工；补齐但未确认仍不能开工。
- 当前材料和实际用户回复绑定，旧摘要不能批准新清单。
- 材料变化阻断恢复、交接及返修；纯截图和内部标注更新保留确认。
- 普通 DLoop、候选交付、最终验收、快照及发行安装回归。

本改动落实项目“以人工决策控制交付”的定位，不改动定位章节，不引入额外审批系统。
