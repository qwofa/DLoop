# DLoop 3.7.6：版本交替与历史归档

基于冻结版 v3.7.5，当前状态为 `frozen`，由 `v3.7.6` 标签固定。本版按用户指定的 3.7.6 补齐版本交替时的工作区退出与档案隔离。

## 需求与处理

- 安装较新版本时不要求旧作业完成、验收、冻结或恢复干净工作区；旧作业整体退出活动流程，原占用记录一起归档，新版不再消费。
- 归档不是完成或验收。批次外层记录已失效，内部业务状态与全部原始文件保留，供追溯。
- 活动材料固定在 `.scratch/dloop-v3/v3.7.6/`，文档、快照、分享和摩擦记录均在该版本目录内。以后发行版本必须使用自己的版本目录。
- 安装较新版本时，将整个旧 `.scratch/dloop-v3/` 移至 `.scratch/dloop-history/<旧版本>-<时间>-<唯一标识>/runtime/`；封存批次同时保存失效说明和交替记录。新版本从空活动区开始，旧文档不会进入新作业的索引、检查、恢复和清理集合。
- 仅读取旧安装的受管文件清单来验证归属和替换工具，不读取或升级旧作业格式。无法证明安装归属时保持原现场并说明原因；不自动降级。
- 已卸载且仍有旧活动材料时，首次安装也将其隔离，来源版本标为 `uninstalled`，不猜测旧版本；同版本在已安装状态下重装保留当前作业，不重复归档。
- 项目代码及既有未提交改动原样保留，不自动回滚、提交或认定验收通过。新作业需重新明确范围和验收，并将现有改动作为实际起点。
- 升级失败时恢复旧载荷、安装锁、档案位置和旧占用记录；成功后输出历史位置。
- 执行升级前停止仍在执行的旧版命令和 Agent。作业可以未结束，但升级期间不能继续编辑、提交或恢复旧作业；安装器检测到命令持有工作区文件锁时拒绝交替。
