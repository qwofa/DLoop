# DLoop v3.9.2 范围、防误报与运行冒烟

状态：`frozen`。冻结日期：2026-09-21。基于公开主线 v3.9.1。

本版不增加审批阶段、需求管理数据库或测试调度器。改动复用开工清单、场景验收记录和统一交付视图，针对实际出现的范围漏登、既有依赖误判和完成误报增加最小约束。

## 行为变化

- 开工清单使用当前版严格合同。初始化登记的每份需求来源必须形成需求，或明确列出本次不交付的结果、来源位置和原因；确认页把排除项置于首部。
- 已有协议或配置使用“沿用既有能力”并引用真实文件；“不涉及”只表示确实没有该类依赖。
- UI 场景验收文件同时记录打开真实入口、看到非空业务内容、正常退出、重新进入或刷新四项最小运行冒烟。未执行可以如实保留，但必要冒烟未通过时不能标记最终就绪。
- `workflow-status` 的交付摘要给出唯一完成口径。固定候选待评审、切片熔断、没有已接受实现或最终验收未完成时，状态不会显示为完成；普通交付即使已封存，仍须用户最终接受才显示完成，导出分享采用相同口径。
- 工作区越界检查忽略当前与遗留 DLoop 自有管理目录；普通临时输出目录仍受保护，避免把真实产品变化整体排除。

## 验证范围

- 开工清单覆盖已登记来源、显式排除、既有依赖引用和确认材料展示。
- 场景验收合同通过公开提交和交付入口验证：四项冒烟结果缺项、已执行却无证据时拒绝候选；未验证或失败时保留成果页但阻断最终就绪；补测通过后恢复就绪；仅重新生成独立冒烟证据也会使旧材料失效，显式交回后才重新就绪。
- 交付视图覆盖候选待评审、候选漂移、验证中、用户接受及冻结状态的完成口径。
- 工作区守卫覆盖当前和遗留 DLoop 管理目录，同时确认普通 `.scratch/outputs` 不被忽略。
- 运行核心、安装与发行回归，并校验两个 Skill 的当前版本合同。

本版没有执行真实业务项目的 Unity 端到端交互；运行冒烟能力的回归验证使用结构化记录与现有交付生成链路。
