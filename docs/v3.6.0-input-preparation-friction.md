# DLoop 3.6.0：输入准备与摩擦复盘

基于冻结标签 `v3.5.0` 开发，发行状态为 `frozen`，由 `v3.6.0` 标签固定。目标是减少字段与路径试错，并保留额外劳动、恢复方式及已有证据，帮助维护者决定下一轮改进。不改变六阶段、业务批准、候选固定或独立评审，不要求重验已验收的 Dev 产品工程；冻结不包含正式安装到 Dev。

## 输入准备

- 任务包的依赖、未知项和材料引用由对应合同提供对象说明、合法值与示例；示例只在返回值中，实际列表按业务填写。业务可用性、批准和验证结果不自动填写。
- `prepare-action-input --input-kind slice-plan --feature-id <id>` 在规范计划目录准备第一版或下一版草稿。方案身份、格式版本和版本号由程序提供；下一版带入当前批准的切片关系，不猜新增范围。
- 草稿采用 `04-plan/slice-plan-vN.json`。无批准方案时准备第一版，有批准方案时准备下一版；已有同版草稿只返回文件位置，保留执行者编辑，不扫描草稿目录建立另一套状态。
- 返回值给出 `target`、`input_guidance` 和 `next_action`，分别表示编辑位置、填写说明和填好后的检查入口。方案检查成功返回绑定本次摘要的批准入口；批准仍重新检查现有规则。
- 协调者在可写的计划或实施角色材料中取得方案准备入口；检查点与候选继续沿用原输入准备路径。

## 摩擦记录

自动失败、尝试、门禁与操作恢复仍按原规则关联。当前记录格式为 2，包含运行版本和当次已有的角色、阶段或执行定位信息。不加载旧版本事件作为当前问题，不迁移旧记录。

新增 `friction-note` 短文本入口：无工具报错时记录额外劳动观察，已有问题用返回的问题身份补充。目标与卡点、实际额外动作和证据是新观察的必要内容；仅用户反馈时明确来源。恢复方式与已知代价可以一次填写，也可以后续补记。

调用示例与输入说明位于 [摩擦参考](../plugin/dloop/skills/dloop/references/friction-records.md)。角色投影、异常和操作恢复结果提供带已有身份的补记入口，不需要为补记创建 JSON 文件或新角色。

补记追加到既有旁路日志，不参与自动异常的关闭判断。自动事件与观察按来源区分；完全相同补记重试不重复追加。记录写入或锁失败只报告不可用，业务结果不变；补记和复盘命令不递归记录自己的失败，也不关闭其他命令的问题。

## 只读复盘

`friction-summary --feature-id <id>` 直接读取该交付项的当前版本日志，按事件顺序输出时间线和问题明细，不先运行全局档案校验。明细包含操作状态、已有恢复说明、额外劳动与证据引用。文件引用只检查存在性，无法读取时保留原记录和提示，不宣称证据内容已经核实。

已经恢复的问题仍然展示；“本次操作恢复”不等于根因修复，“恢复方式未记录”不等于作业仍阻塞。事件去重后的数量不是完整调用次数，时间间隔不是工作耗时，不输出推算的成功率、Token 或成本。

已有只读分享入口按交付项导出新事件，不新增正式复盘档案、问题修复状态、后台任务或自动聚类。必要评审、正常讨论和产品缺配置不自动计为流程摩擦，只有实际多做的工作需要就近说明。没有说明或恢复记录不阻断提交、评审和冻结。

## 验收范围

- 按生成的嵌套示例填写依赖、未知项与章节引用，经过公开契约登记和检查。
- 通过实际返回入口完成方案检查、批准、换版及重复准备，确认不覆盖编辑或历史。
- 验证无异常观察、同问题恢复补记、正常门禁上的额外劳动、去重与自动关闭相互独立。
- 在最终检查点与提交、评审之间追加记录，确认业务状态与候选有效；分享中保留观察。
- 模拟记录不可写，确认无递归日志及业务变化；没有可校验业务档案或引用文件时仍可只读复盘旁路事实。
- 运行相关工作流、发行与临时安装卸载检查；不自动安装到目标项目，也不以真实模型效率收益作为本次验收通过的依据。
