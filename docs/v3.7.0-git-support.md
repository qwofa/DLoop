# DLoop 3.7.0 Git 项目支持

## 版本与目标

用户要求新开版本，让 DLoop 能用于 Git 项目。基于已冻结的 `v3.6.8`（标签提交 `v3.6.8`）开发，新增受支持的版本管理类型，目标版本为 `3.7.0`。2026-09-11 经用户授权冻结并通过 PR 合入主分支，当前状态为 `frozen`，由 `v3.7.0` 标签固定；本次冻结不包含安装到用户项目。

## 当前实现范围

- 保留 Windows 安装环境，支持 SVN 工作副本、Git 普通仓库、Git worktree 和仓库内项目子目录。按项目最近的版本管理元数据选择类型，不要求 Git 项目安装 SVN。
- 安装、校验、卸载复用现有受管文件事务；Git 项目须预先忽略项目下的 `.scratch`，安装器检查有效规则，不改写忽略配置。
- 实施基线与检查点绑定仓库修订、暂存状态和内容、未暂存内容、新增及删除文件；改名作为旧路径删除与新路径新增检查。保留单线修改资格、范围校验、独立评审、最终确认与自动封存。
- 候选产物清单保留新增与修改文件的正文摘要；后续切片启动、状态展示和最终验收按实际执行顺序复核全部已接受产物，同一路径以最后一次接受的结果为准，删除结果也须保持。该检查包含被 Git 忽略的明确产品产物，不扫描其他忽略缓存。
- Git 检查只读，不自动暂存、提交、推送、切换分支或重置索引。已有暂存内容保持原样；撤销本轮沿用授权范围正文恢复。SVN 继续自动纳管与归组，Git 跳过该项，不仿造 Git 提交组。
- 支持尚无首次提交的仓库与 detached HEAD。不跨子模块实施；启动前按已登记的子模块边界检查授权范围，直接写入子模块或授权其父目录均拒绝，不依赖产物是否已生成或被忽略。遇子模块变化明确停止，需在子模块项目内独立运行工作流。普通无版本管理目录仍不作为实施工作区。
- 仅处理当前版本作业，不增加旧作业迁移、通用版本管理插件层或新的工作流状态。

## 验证计划

使用真实临时 Git 仓库和 worktree 验证安装、校验、卸载，暂存与未暂存混合修改，中文及空格路径、增删改名、范围外修改、版本漂移和中断恢复。通过已安装命令走完实施、候选评审、集成与自动封存；运行现有 SVN 回归和发行一致性检查。

Git 状态格式和只读选项依据 [Git status 官方文档](https://git-scm.com/docs/git-status)，忽略规则验证依据 [Git check-ignore 官方文档](https://git-scm.com/docs/git-check-ignore)。
