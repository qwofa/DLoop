# 额外劳动与恢复方式

只在用户明确反馈，或实际发生重复解释、材料查找、格式试错和交接退回等额外劳动时记录。正常业务讨论、必要评审、产品缺陷与业务缺配置不自动算工作流问题；正常门禁正确但造成了明确重复劳动时，可以补充这部分代价。

当事角色就近记录，用户反馈由收到反馈的协调者记一次。已有问题使用返回的身份，不让其他角色重复登记，不为记录增加一次交接。

外部工具的脚本重载、连接恢复、能力缺失和项目同步若造成实际额外动作，也使用同一入口补记；不要求另建环境日志。收尾只回看本次已经知道的返工和汇总的补记候选，补足遗漏的恢复方式，不重新遍历全部会话。汇总明确区分自动门禁、实际额外动作、已报告代价和未知代价；没有计量不写零，没有重复证据不写“未重复”。这些信息不作为新的交付门禁。

新观察使用 `friction-note --feature-id <id> --summary "目标与卡点" --extra-work "实际多做的动作" --evidence "来源"`。工具接收短文本，无需准备 JSON 文件。文件证据使用 `path:项目相对路径`，执行或评审身份直接引用；只有用户反馈时使用 `--source user-feedback`，不伪造文件证据。可附当次已知的 `--role`、`--stage`、`--execution-id`；角色视图提供已填好定位信息的 `friction_note` 入口。

已有自动异常或观察用 `--incident-id <返回的问题身份>` 关联。恢复时追加 `--recovery "关键改动与结果"`，有可信代价时可加 `--cost "次数或耗时、单位与依据"`；后来确认的代价可以单独补记，无需重复填写观察或恢复说明。发现时已经恢复可一次填写观察与恢复；相同补记重试不重复追加。不了解实际代价时省略，不专门计时，不用事件时间差推算投入。

`friction-summary --feature-id <id>` 只读呈现时间线、每个问题的自动操作结果、观察、恢复方式和证据入口，也保留已经恢复的问题。操作恢复只表示这次命令后来成功，不代表流程根因已修复；恢复方式未记录不表示业务仍然阻塞。记录覆盖不完整，事件数不是调用次数、发生率或投入成本。

补记只写旁路日志，评审者仍不修改产品、正式材料和候选。记录失败只提示，不递归记自身失败；没有补记或恢复说明不会阻断启动、提交、评审或冻结。摩擦可随现有只读分享导出，不另建业务历史或修复状态机。

复盘同时查看汇总中的 `execution_breakers`：它直接读取现有检查点熔断报告，包含触发事实、成果和未完成项以及当前切片状态，不重复写入旁路日志。已终止或继续的切片仍保留历史熔断，不据此认定根因已修复。文档级命令在目标属于同一交付项时自动归属；跨交付项批次仍保留全局归属。
