# DLoop v3.7.5 中间态保存与恢复

## 自动保存与编辑边界

所有作业都使用独立本地 Git 快照库，SVN 项目也必须有 Git 客户端。库位于 `.scratch/dloop-v3/snapshots/<feature-id>.git`，不改变源项目 Git 分支和暂存区，不提交 SVN 服务器。快照是持久数据，不作为缓存清理。

工具自动保存作业起点、切片与返修开始、每个合法检查点（包括失败或熔断）、固定候选、评审、批准、确认材料、UI 发布及交付冻结结果。工具显示保存失败或 `recovery_required` 时，先运行 `snapshot-recover --feature-id <id>`；未成功前不得编辑、交接或启动新实施。

协调者在每个实际开放阶段首次开始编辑前运行 `snapshot-save --feature-id <id> --reason stage-start --stage <stage>`。阶段按 `requirements`、`investigation`、`design`、`plan`、`implementation`、`validation` 使用现有名称，未启用的阶段不保存空点。同一轮次相同阶段不要重复标记开始；重做成功后新一轮重新保存。只读查询不写保存点。

准备覆盖旧方案、重新生成材料或替换一批已有成果前，运行 `snapshot-save --reason before-overwrite`；提交阶段材料给评审或等待用户确认前运行 `snapshot-save --reason stage-submitted --stage <stage>`，阶段完成时运行 `snapshot-save --reason stage-completed --stage <stage>`，均附交付项。一次连贯编辑只在批次边界保存，不逐文件、逐命令、逐截图保存。

用户要求暂停或跨上下文交接时，先停止受影响写入，再 `snapshot-save --reason pause`。从中断恢复时，先检查现有执行身份和恢复要求，保存当前可读取的现场（`--reason resume`），再交回原执行者。强制结束只能保证上个成功保存点；长实施阶段完成有意义的一段工作后应登记检查点，不等整个切片结束才保存。

用户要求“这里存一下”时运行 `snapshot-save --name <业务名称>`。可用 `--request-id` 标识一次手动请求，重试保持相同标识；文件已变更时使用新标识。保存成功不意味着测试通过，必须如实保留失败和未验证结果。

## 查看、回退与阶段重做

1. 运行 `snapshot-list --feature-id <id>`，按业务名称、阶段、时间、原因和验证结论选择保存点；不能猜保存点编号。
2. 只看历史或取旧文件：运行 `snapshot-export --feature-id <id> --snapshot-id <编号> --destination <新目录>`。导出不修改当前项目，覆盖范围见导出清单。
3. 用户要求恢复并继续时，停止当前写入，用 `snapshot-restore --feature-id <id> --snapshot-id <编号>` 取得实际文件与切片影响预览；重做阶段使用 `--stage <stage>`，默认选择该阶段最近一次开始前的输入。
4. 目标与处置范围已明确时，在核对预览后加 `--execute` 执行，不重复向用户索要已有授权。只有“回退一下”且上下文无法确定目标时才问缺失信息。恢复工具会先保存回退前现场，失败不会覆盖当前内容。
5. 恢复后重新运行 `workflow-status`，按返回的当前事实继续。当前实施或待评审候选会以准备好的契约重开，用新的执行身份启动；旧身份不能续写，检查点、评审和验证不能冒用。历史在原保存点可查，后续受影响候选退出当前结果集合。
6. 按原阶段输入重新评估需求、设计、计划和下游依赖；工具保留未变上游批准，最终确认需重新验证。需求、架构或交互发生语义变化时沿用原批准失效规则，不把快照当作用户重新批准。

原切片内简单返修仍走既有返修入口；用户明确要恢复某一保存点时才使用恢复入口。恢复前保存点可以再次恢复，允许撤回此次回退。不得伪造评审失败、编辑状态文件或全仓重置来取得恢复资格。

## 冻结、导出与清理

冻结作业只能查询和导出。需要继续 DLoop 时运行 `snapshot-fork --source-feature-id <旧作业> --snapshot-id <编号> --feature-id <新作业> --title <标题>`，工具导出旧材料并创建带来源的新作业；根据导出材料重新登记目标、范围及批准后实施，不直接把旧批准复制成新作业批准，也不覆盖源工作区。

源仓库修订或分支改变时不自动覆盖或合并，导出历史作为新的变更作业输入。没有跨版本恢复。快照在本地，未配置远端备份。

状态显示保存数量与占用空间。默认保留全部保存点，磁盘不足则停止推进；缓存清理和卸载保留快照。完整作业清理预览会同时列出快照库，用户明确清理后才一起删除。普通分享导出不自动带出完整代码历史。
