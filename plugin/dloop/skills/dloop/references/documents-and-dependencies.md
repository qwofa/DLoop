# 文档、依赖与图示

## 六类职责

- 需求：用户确认的目标、范围、业务决策、验收条件和访谈上下文。
- 调查：仓库、环境和外部证据所证明的事实与未知。
- 设计：基于需求与证据选择的方案、职责、行为和取舍。
- 计划：交付结果、顺序、依赖、完成条件、验证和回滚。
- 实施：工作区实际变化、计划偏离、执行结果和遗留问题。
- 验证：实际证据、结论、未验证边界和残留风险。

内容简单时每类只维护入口；入口不足以承载证据时才增加专题文档。事实类型不得互相冒充。

依赖只能从上游职责指向下游；同层资料使用 `related_documents` 关联。例如计划总览引用 UI 标注附件时，不把两个计划文档登记为硬依赖。

## 调查并行边界

只有互不依赖、只读且能分别返回证据的问题可以由主协调者通过原生子 Agent 并行调查。分发前固定每个问题、允许材料和停止条件；分支不得写入项目或档案、作出需求或设计决定，也不得继续派生问题。主协调者等待全部结果后去重、核对矛盾，并以单一上下文写入正式调查结论。问题存在前后依赖、共享可变环境，或拆分与汇总成本不低于预计节省时间时保持单线。

## 写作最小规则

每个入口独立说明当前要判断什么、当前结论和最重要范围边界。局部业务行为只在必要范围明确主体、触发、操作和可观察结果；状态变化和不处理条件只在影响判断时补充。能删除且不影响目标读者判断的解释应删除。

需求与验证入口直接承载面向人的场景正文；细节按需展开或链接，影响批准的范围与偏差保持直接可见。场景名称沿用到计划和验收，不另外维护人类摘要或复制一套规格；生成入口中的填写提示在形成正式正文时删除。

设计从已批准场景及其原始来源核对操作去向、信息含义和结果范围；复用页面存在差异时明确实际要改什么，不把现有资产当成需求。显示信息按需落实到对象、区域和已核实的数据来源，源数据尚不明确时记录具体缺项，不能用空值或另一种排序结果冒充完成。

涉及到期、回包或重新进入引发的状态变化时，说明触发者、获取新事实的动作、事实返回后的界面更新，以及新事实未到或条件仍不满足时的表现。触发条件到达后先获取新事实，界面变化仍依据权威数据；不能只写“收到更新后刷新”，也不因此引入轮询、重试或第二套业务状态。

## 按交付结果拆分计划

协调者从完整业务流程选出可分别接受或退回的结果，再形成实施切片。同一结果所需的代码、配置、接线和验证通常留在一个切片；仅因它们属于不同技术层或文件，不拆成单独交接。两个切片必须同时修改同一责任、互相等待或无法分别验收时，优先合并或先明确共同依赖。独立的基础能力确有消费者和可观察完成条件时可以先做，不为未来可能的复用预建基础层。

多个切片共享接口、数据归属或执行顺序时，在现有设计中作出一次共同决定，各契约引用同一依据；不让不同实施者分别猜测。关键未知会改变拆分时先在调查阶段查明，必要时先交付贯通关键依赖的最小可用流程，再扩展剩余场景；已有项目事实足够时不强制增加探索任务或原型。

在现有计划正文用简短列表或表格关联需求场景、切片结果、前置依赖和验收依据，沿用场景名称及切片标识。延期、复用或依赖缺失的结果也须有明确去向；缺项补承接、补依赖或走已有范围变更，不另建覆盖账本或场景状态机。已有正文能够直接查到对应关系时不另建表；责任、验证和回退细节只引用现有设计及契约，不复制正文或增加机器字段。

形成首版方案时由协调者整体核对：必要场景均有承接；切片责任没有重叠或漏项；依赖顺序可执行且关键未知有处理去向；每次拆分带来的独立验收价值值得一次交接。检查发现问题就修正具体边界，简短记录结论与仍待解决项。它是计划阶段的语义自检，不新增独立计划评审角色、人工批准或评分门禁；需要独立设计评审时仍按既有触发条件进行。

当前要启动的切片补足完整契约；后续切片先保留结果、边界、依赖和验收方向，临近实施再细化。不能借延后细化省略整体范围或共同决定，也不要求预先列出所有内部编码步骤。

## 文本编码

- 交付档案、工作流规则和机器 JSON 统一使用 UTF-8 无 BOM；工具生成或重写的文本统一使用 LF。
- PowerShell 读取文本时必须显式指定 UTF-8，例如 `Get-Content -LiteralPath <path> -Raw -Encoding UTF8`；不得依赖宿主默认代码页。
- 不得使用未显式指定编码的 `Get-Content`、`Set-Content`、`Out-File` 或重定向符修改交付材料；项目写入使用确定性工具或补丁编辑。
- 无法按 UTF-8 读取时立即停止并报告具体文件，不得忽略或替换非法字节，也不得猜测 GBK、ANSI 等其他编码。历史异常文件只在用户确认原始编码后单独转换并复核差异。

## 图示

结构化图示只用于压缩需要跨章节拼接的流程、状态、职责、数据流或任务依赖，不装饰文档。出现以下任一关系复杂度时优先考虑图示：三阶段以上且有分支循环；三个以上状态且转换影响行为；一个来源影响三个以上下游；三个以上任务存在非线性依赖；完整关系分散在两个以上章节。

流程用流程图，状态转换用状态图，方向用流向图，任务先后用依赖图，重复映射用表格。一张图只回答一个主要问题，保持同一主体层级和事实类型；不得增加上游材料和正文没有确认的新节点。图和正文冲突必须修正；删除图后几乎不影响理解时，应删除或简化重复、装饰性图示。

不设置固定图数量，不为所有文档预建空图章节；只有一个节点且没有关系时不加图，严格串行任务使用编号列表。

## 长期文档边界

交付档案是执行记录，不自动成为正式文档、长期知识文档或知识库。只有用户在当前任务中明确指定目标并要求更新时，才允许把交付档案内容沉淀到这些长期载体。

## 文档变更与新鲜度

一个编辑批次完成后，只对实际修改文档执行一次确认。业务规则、状态、接口、范围或验收变化提交语义变化；排版、错字或无含义变化的措辞提交非语义变化。工具负责版本、直接失效和刷新队列，Agent 不根据时间或文本差异模拟。

使用设计、计划或下游输入前运行刷新队列和新鲜度断言。文档元数据是依赖事实源，普通链接不替代依赖；不得手工编辑派生索引。
