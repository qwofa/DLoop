# v3.4.2 基线审计与改写原则

## 已审计事实

- 常驻入口为 8192 字节、92 行，已经达到现有发行测试上限；六份动作参考合计约 39.6 KB，其中实施闭环参考约 17.4 KB。
- 动作到参考规则的映射由确定性代码维护，能按请求顺序稳定去重并投递完整 UTF-8 正文；未知动作、缺失文件和非普通文件会在返回部分规则前失败。
- 统一交付视图从档案、批准、执行身份、租约、新鲜度和候选即时派生唯一下一动作。实施、候选评审和最终验收角色视图全有或全无。
- 状态机已经强制执行写入范围、活动身份、候选固定、自审拒绝、普通失败不熔断、真实边界变化熔断、批准新鲜度、最终候选漂移和清理事务。
- 普通 DLoop 与 DloopUI 共享状态机，但普通初始化没有 UI 配置或 UI 产物；只有显式 UI 配置允许 UI 命令。
- 现有 348 个 `unittest` 主要证明命令、状态和发行合同。它们不能证明模型实际选了哪个动作、读了哪些材料、是否重复调用、是否在机器阻断后停止，以及交接质量。
- 既有 skill 测试仍有较多固定中文短语断言。这些可保留为少量发行结构烟测，但不应成为行为改写的主要成功标准。

## 直接用于本轮的设计原则

| 原则 | 仓库内落点 | 行为证据 |
| --- | --- | --- |
| 渐进披露 | 常驻入口只保留工作流地图、关键不变量、动作路由和停止条件；动作细节由 `workflow-rules` 投递 | 无关读取、重复加载、角色越界读取 |
| 短入口与按动作路由 | 入口不重复参考正文和机器返回字段；动作映射继续只由确定性代码维护 | 选择正确动作并只读命中材料 |
| 明确完成条件 | 每类角色说明何时继续、何时提交、何时阻断并交还协调者 | 最终状态、停止原因和交接对象 |
| 正反例与合理化 | 只保留高风险分叉：普通测试失败不是熔断；合同边界失效才熔断；预览不等于删除授权 | 范围内失败、真实边界变化、清理双场景 |
| 确定性代码承载硬约束 | 身份、状态、写入范围、批准、漂移、清理资格和字段合同以命令结果为准 | 硬门槛检查状态与写入，不检查固定措辞 |
| 用结果而非措辞评测 | trace 记录读取、决定、命令顺序、状态、写入、停止和交接 | grader 只匹配结构化语义事件与最终状态 |

## 本轮改写边界

- 不重写状态机，不新增兼容、恢复、重试或第二份持久状态。
- 优先删除入口与参考中的重复机器合同；保留 explicit-only、角色材料边界、专项授权和所有现有安全门。
- 实施闭环参考先按“角色入口—正常路径—例外停止点—确定性命令”收敛；字段枚举和状态合法性继续由输入生成器、角色视图和命令错误返回。
- baseline/candidate 的模型 dry-run 与状态机单元测试分开报告。前者是自报语义 trace，不冒充实际 CLI 集成运行；后者不冒充模型行为。
