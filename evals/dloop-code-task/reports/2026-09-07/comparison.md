# 3.6.1 / 3.6.2 独立编码对照

2026-09-07，两个无前序对话的原生 Agent 使用相同任务、相同初始产品文件和各自版本的实际 CLI，在独立本地 SVN 工作区完成“批量处理条目”。均从已启动的实施角色开始，真实生成代码、运行测试并提交候选；未进行自评或用户批准。两次派发沿用同一父级模型和推理配置，未单独覆盖。

| 实际观察 | 3.6.1 | 3.6.2 实验快照 |
| --- | --- | --- |
| 提交结果 | candidate，等待独立评审 | candidate，等待独立评审 |
| 项目测试（含既有单件行为） | 9 / 9 通过 | 11 / 11 通过 |
| 事后独立业务断言 | 7 / 7 通过 | 7 / 7 通过 |
| 交接准备响应大小，紧凑 UTF-8 JSON | 6,663 字节 | 785 字节 |
| 实施者报告的时钟读取范围 | 06:47:21–06:49:00 UTC | 06:47:31–06:49:20 UTC |
| 对应一次墙钟时长 | 99 秒 | 109 秒 |
| 实施者报告的额外劳动 | 无阻塞或异常返工 | 为保存原生日志多跑一次测试 |
| token、工具次数、重复读取总数 | 未取得 | 未取得 |

独立断言覆盖取消、空选择、重复输入、受保护条目、缺失条目、关联数据更新失败和重复确认；同时检查失败后的数据恢复与既有集合引用。两份实现的业务逻辑相同，均复用共享存储事务，没有新增抽象或修改共享存储。

这次样本证明两份候选都满足所列局部业务条件，且交接准备返回体减少约 88%；不能据新增测试数量断言代码更好，也没有证据证明整体提速。时间来自实施者返回的实际时钟读取值，不是完整宿主调用 trace；两次模型并行运行，资源竞争和随机性都未控制。项目验收未包括 Unity、真实用户操作或完整六阶段交付。

实验暴露了一次为了保存日志而重复验证的额外劳动，随后在现有实施规则中明确优先引用已有可复核原生结果。实验结束后的独立审查还补上检查点输入的契约版本校验。这两项后续收口由回归及角色投递检查覆盖，未重新执行整轮模型对照；本报告描述的是保存下来的实验快照，不冒充最终全部规则的再次实测。
