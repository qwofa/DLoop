# DLoop

**少重复解释，少反复催办，少费力验收。**

## 它能帮你做什么

- **持续推进，减少催办。** 在已确认范围内推进实现、评审、修正和验证，尽可能减少中途打断，无需每一步都由你安排。

- **拆分需求，为上下文减负。** 将完整需求拆成可执行的任务，按任务组织相关背景、约束和已确认结论，减少无关信息干扰和重复解释。

- **减少漏需求和需求偏移。** 从原始需求提取业务场景，贯穿设计、实施与评审；验收时对照场景检查结果与差异，需要扩大改动范围时交由你决定。

- **让审核文档短而清楚。** 优先呈现目标、操作、效果、关键条件和待决定事项，方便你集中判断是否符合预期；过程细节保留查阅入口。

- **保留中间成果，支持按阶段重做。** 自动保存任务进度与中间成果。需要调整方向时，可以先保留当前现场，再恢复历史或重做阶段，减少从头开始的成本。

- **可视化呈现 Unity UI 成果。** 结合真实截图与交互说明，让你直观看清 AI 实现了哪些功能、操作会产生什么反馈，以及交互是否符合预期。

- **集中交接，明确剩余事项。** 交付时汇总完成情况、待补充内容和需要你处理的事项，如实列出未完成与未验证部分，减少翻查记录和逐项追问。

## 安装

需要 **Windows、Python 3.10+、Codex、已连接的 Unity MCP、Git 客户端，以及 Git 或 SVN 项目**。Unity MCP 不限实现或版本，但须满足当前项目操作与编辑器内采集所需能力。首次安装请先完成[依赖准备与连接检查](docs/dependencies.md)，再在 Unity 中打开目标项目。

在**目标项目根目录**打开 PowerShell，运行：

```powershell
irm https://raw.githubusercontent.com/qwofa/DLoop/main/install.py -ErrorAction Stop | python -
```

当前发行版为 **v3.7.3**，状态为 `frozen`，由 `v3.7.3` 标签固定。上面的一行安装入口固定下载对应版本，准备项目、安装 DLoop 与 DLoopUI，并校验安装结果。看到 `DLoop installed and verified.` 即表示项目内载荷已安装并校验成功。本地及离线方式见[安装说明](docs/installation.md)。

随后在 Codex 中打开这个项目，选择下面任一入口开始。Codex 和 Unity MCP 是已有环境依赖，本命令安装的是 DLoop。

## 使用教程

附上需求文档，选择对应入口并说明目标即可。需求整理、实施、评审和验证由工作流按默认流程组织。

### DLoop：推进一项长任务

在 Codex 中输入：

```text
$dloop
根据我提供的需求文档完成本次功能。
```

### DLoopUI：修改界面并可视化验收

涉及 Unity 界面、布局或交互改动，希望通过截图与交互说明验收时，输入：

```text
$dloop-ui
根据我提供的需求文档完成本次功能。
```

DLoopUI 默认在实施中补齐原范围内有依据的交互，并在交付时集中展示界面成果与验证情况，供你验收。

### 追加自定义要求（可选）

如有本次任务特有的范围、优先级或验收要求，直接追加在提示词后面，例如：

```text
本次只完成需求文档中的第一阶段。
界面需要同时适配横屏和竖屏。
```

没有额外要求时，使用上面的最短提示词即可。没有需求文档时，也可以将目标句替换为具体需求描述。

### 继续、调整或暂停

回到项目后，直接说清功能名称和意图：

```text
$dloop
继续“<功能名称>”任务，从当前进度往下推进。
```

```text
先暂停“<功能名称>”，保留当前成果。我需要调整需求。
```

工作流根据已保存的进度处理。涉及 UI 方案的任务继续使用 `$dloop-ui`；你也可以直接指出需要调整的行为，由工作流整理影响并重新呈现需要确认的部分。

## 审核时，你会看到什么

文档按业务场景组织，帮助你快速对照预期。例如下面是**内容形式示例**：

> **场景：一次用户操作**
>
> **操作与效果：** 说明操作入口、执行条件和用户能够观察到的变化。
>
> **关键约定：** 说明应当保留的现有行为，以及条件不满足时怎样处理。
>
> **请你确认：** 以上操作、结果和边界是否符合预期？
>
> **界面定位：** 涉及 UI 的任务附真实截图与修改标注。

确认前看目标、效果和取舍；交付时沿相同场景查看实际结果、偏差和未验证部分。详细设计、评审和验证记录仍可继续查阅。

```text
你给出需求
    ↓
整理需求、调查项目、形成设计与计划
    ↓
你集中审核范围、设计和交互方案
    ↓
分步实施 → 独立评审 → 返修与验证
    ↓
查看交付结果与需求差异
```

流程会按实际情况设置确认节点；影响预期的新变化仍需你判断。
